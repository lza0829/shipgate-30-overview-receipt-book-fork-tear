# 发版闸（Shipgate）

骨架：发版申请入闸 → 环境晋升裁决 → 放行/回滚窗 → 发布结果对账

- 前端 http://127.0.0.1:6800
- API http://127.0.0.1:11800
- 数据库环境变量 `SHIPGATE_DB`（容器内默认 `/data/shipgate.db`）

```bash
docker compose up -d --build
```

## 环境分布真源（定臂）

**采用「晋升放行事件重投影」臂，全系统唯一真源为 `distribution_events` 分布事件流。**

环境分布（总览四格、应用名册各环境版本、发版单当前环境、对账汇总）只能由该事件流
按 id 顺序重放得到，禁止各处各写一份 SQL COUNT。

- `app_env_versions`（名册三环境版本列）与 `releases.current_env_id`（发版单当前环境）
  都是**投影缓存**，只允许 `app/services/projection.py` 重放写入；命令侧
  （入闸/晋升/回滚）不得直写（旧的直写函数已删除）。
- 每条命令（入测/晋升/回滚）追加一条分布事件后，在**同一数据库事务内整体重投影**
  （同命运）：要么事件与缓存一起生效，要么一起回滚，读端观察不到半截/双数。
- 晋升推进与总览刷新因此不存在撞车窗口；并发读只可能读到更早或更晚的完整代次，
  投影任务号、事件位点单调不减，不会回闪旧分布。
- **纠偏口**：`POST /api/投影/重放` 以事件流为准整体重写缓存，返回重放前后差额与
  纠偏行数并写审计。缓存与事件流分叉（缺事件、半截写入）时对账页显式暴露差额，
  一次重放即归零，不允许长期双数。
- **空事件集语义**：重放结果为全空名册、发版单全部「未落地」，不保留旧缓存。
- 金丝雀比例另有真源（`releases.canary_ratio`），分布重投影不触碰该字段，二者错开。
- `promote_events` 仍是闸口裁决流水（放行/拒绝留痕），不等同于分布真源事件流。

### 同源对照面

| 位置 | 字段 |
| --- | --- |
| 总览页 `GET /api/总览` | 环境分布四格、名册版本、投影任务号/刷新戳 |
| 应用名册 `GET /api/应用名册` | 三环境版本列与版本戳、同一投影戳 |
| 晋升入口 `GET /api/分布事件` | 分布事件流（真源）、四格、差额、投影戳 |
| 对账页 `GET /api/对账` | 四格、缓存 vs 事件流差额、投影戳，含重放纠偏按钮 |
| 审计 `GET /api/审计` | 审计流水 + 投影刷新戳（重投影任务逐次留痕） |

投影任务账本 `projection_meta`：任务号单调递增，记录事件位点、刷新戳、触发方与纠偏行数。

## 测试

```bash
cd backend
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt httpx pytest
SHIPGATE_DB=/tmp/sg_pytest.db python -m pytest tests/ -v
```
